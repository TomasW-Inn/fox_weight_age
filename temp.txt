Yes, bioRxiv is a very suitable preprint server for this manuscript — it's the standard choice for ecology and evolutionary biology, and your paper fits well within that scope.

Regarding supplementary materials, data, and code: bioRxiv does allow you to upload supplementary files alongside your manuscript, so your supplement.pdf can go there directly. However, for data and code, bioRxiv is generally not the best or most appropriate home. The community norm — and increasingly a requirement at journals you'd later submit to — is to deposit these in dedicated repositories:

For data, good options include Dryad (https://datadryad.org), Zenodo (https://zenodo.org), or the Open Science Framework (https://osf.io). These issue DOIs, making your data properly citable and permanently archived.

For code (your JAGS model scripts, R analysis code, etc.), GitHub is the most common choice for version control and visibility, but it's best paired with Zenodo, which can archive a GitHub release and issue a DOI — since GitHub alone isn't a stable long-term archive.

A practical workflow many ecologists use: deposit data and code on Zenodo (or Dryad for data), get the DOIs, then reference those DOIs in your manuscript and bioRxiv submission before uploading. That way everything is linked from the start.

Given that your study uses a fairly specialized hierarchical Bayesian state–space model in JAGS, sharing the model code would be particularly valuable to readers wanting to replicate or build on your approach.

Start a new chat for one-off or loosely related tasks — quick questions, standalone analyses, or things that don't build on each other over time.
Use a Project when you have a body of work that develops over multiple sessions, which sounds exactly like your situation with the fox life history manuscript. Projects are well-suited when you:

Want Claude to remember context across conversations (your study area, species, methods, co-authors, writing style preferences)
Are building something iteratively — drafts, analyses, revisions
Have files (data summaries, draft text, references) you want consistently available across sessions

So for the fox manuscript, I'd suggest creating a Project. You could give it a name like "Fox life history analysis" and from the start add any relevant context — a brief description of the study, the kind of data you have, your target journal, etc. That way you won't need to re-explain your setup every time you start a new conversation within the project.
